How derivatives work in jolty

One message, explained line by line: what a circuit's equations are, where every derivative in jolty comes from, why they are one process mathematically and several today in the API, and what would make them one in the API too.

1. Background: voltage, current, devices, components

Voltage is the electrical "height" of a point in a circuit, measured in volts (V) against a reference point called ground, which is 0 V. Every connection point, called a node, has one voltage.

Current is the flow of charge through a wire or a part, measured in amperes (A). It flows from higher voltage to lower voltage through a part that lets it.

A device is one physical part with a law that ties the current through it to the voltages at its terminals. Three examples:

DeviceIts lawIts parameters
Voltage sourceHolds its terminals Vs volts apart, whatever current flowsVs
ResistorCurrent = (voltage across it) ÷ R, Ohm's law; linearR, in ohms (Ω)
DiodeCurrent = Is·(eV/Vt − 1): almost nothing below about 0.6 V, then a steep rise; nonlinearIs, the saturation current; Vt ≈ 0.02585 V is fixed by temperature

A transistor is a device too, with more terminals and a far longer law (BSIM4 runs to thousands of lines), but the same idea: currents as a function of terminal voltages and parameters.

A component, in jolty, is a Python function that places devices (or other components) and wires their terminals together. It is a recipe, not a new kind of physics:

@component
def divider(c: Builder, upper: Quantity, lower: Quantity) -> None:
    top, tap = c.port("top"), c.port("tap")
    ground = c.port("ground", Role.GROUND)
    first = c.place(devices.resistor(upper), name="R1")
    second = c.place(devices.resistor(lower), name="R2")
    c.connect(top, first.a)
    c.connect(first.b, second.a, tap)
    c.connect(second.b, ground)

Before simulating, jolty flattens every component into the devices it contains. The engine only ever sees devices and the nodes that join them.

2. The circuit's equations, F(x, p) = 0

Everything below uses one small circuit: a 1 V source drives a 1 kΩ resistor into a diode. The one node between them, call it x, is the only voltage we do not know.

Where the equation comes from. Charge does not pile up at a node, so whatever current flows into node x must flow out (Kirchhoff's current law). Writing "current out through R plus current out through the diode = 0":

F(x, p) = (x − Vs) / R + Is·(ex/Vt − 1) = 0

That is all F is: the sum of currents (in amperes) leaving each node, which must be zero. It is never a sum of voltages. Each term is one device's current:

TermWhich currentWhy it looks like that
(x − Vs) / RThrough the resistor, from node x back towards the sourceOhm's law: the voltage across the resistor divided by its resistance. Its two ends sit at x and at Vs (the source holds that end at 1 V), so the voltage across it is x − Vs.
Is·(ex/Vt − 1)Through the diode, from node x down to groundThe diode's law, with the voltage across it x − 0 = x.

The source adds no term of its own here because it does not touch node x: it only fixes the voltage at the resistor's far end, which is where Vs enters. Adding Vs itself as a term would add volts to amperes. (In the engine, the resistor's far end is a node of its own with its own equation, and the source adds one more unknown, the current it supplies, and one more equation, "this node is at Vs". Here those two are solved by hand to keep one unknown.)

Here:

  • x = the unknowns: the voltage at node x (a bigger circuit has one per node, plus the current through each voltage source).
  • p = the parameters: Vs, R, Is, and in your project, a crossbar's weights.

A circuit of n unknowns has n such equations, one per node. jolty builds F by asking every device for its currents and adding each into the equation of the node it touches. In short: F: (n unknowns, P parameters) → n currents, and simulating means finding the x that makes all n currents zero.

3. Solving them: Newton's method

There is no formula for x here: the diode's exponential makes the equation impossible to solve by algebra. So jolty guesses, then corrects. At each guess it asks two things: how far off is it, F(x), and how fast does F change as x changes, the slope ∂F/∂x. Then it jumps to where that slope says F would be zero:

xnext = x − F(x) / (∂F/∂x)
StepGuess x (V)F(x) (A), the error

With n unknowns, the slope becomes an n × n table, the Jacobian J = ∂F/∂x: entry (i, j) says how much node i's current changes when node j's voltage moves. Each Newton step solves the linear system J · Δx = −F (jolty does that with a sparse LU factorization), then moves x ← x + Δx. At the answer, J = 0.01535 A/V here.

4. The message, quoted and explained

Is there one coherent way derivatives work? Yes, in the maths. No, in the API. That's where the real debt is.

"The maths" is how jolty computes derivatives inside: one consistent method. "The API" is what you, the user, call to ask for a derivative. Today you call different things for different analyses, and none of them is the shape JAX asks for. So the inconsistency you sensed is real, but it lives in the user-facing layer, which can be refactored, not in the engine's foundations.

The maths has one source and three layers, each the chain rule applied to the same object: the circuit's equations F(x, p) = 0, where x are the node voltages and currents and p the parameters.

"One source" is F from section 2: every derivative jolty can give comes from differentiating that one function. The "three layers" are three places the chain rule is applied, from the smallest scale to the largest:

Local, inside each device: every device kernel computes its equations on dual numbers.

A kernel is jolty's code for one device's law, for example the diode's I = Is·(eV/Vt − 1). It is written once, in Rust.

A dual number is a number that carries its own derivative along with it. Write it a + b·ε, where a is the value, b the derivative, and ε a symbol with one rule: ε² = 0. Arithmetic then does calculus by itself:

(a + bε) · (c + dε) = ac + (ad + bc)ε + bd·ε² = ac + (ad + bc)ε ← the product rule ea + bε = ea + ea·b·ε ← the derivative of exp

So if you evaluate a function on a + 1·ε, the result is f(a) + f′(a)·ε: its value and its exact derivative, with no finite difference and no rounding beyond the arithmetic itself. In our circuit, evaluating the diode at V = 0.629 + 1·ε returns its current and the current's slope with respect to V in one pass.

jolty's version, Dual<R, N>, carries N derivatives at once (a value plus a gradient array), one per input of the device: a transistor with four terminals gets four.

Seeded on the voltages, they give ∂F/∂x, which Newton uses.

Seeding means choosing which derivative a dual number tracks, by setting its starting derivative to 1. Each terminal voltage Vi enters the kernel as Vi + 1·εi (derivative 1 with respect to itself, 0 with respect to the others). Every current that comes out then carries ∂I/∂Vi for each terminal.

Those are exactly the device's entries in the Jacobian J = ∂F/∂x of section 3, because x are the node voltages and F sums the devices' currents. Newton needs J at every step to know which way, and how far, to move. That is why every circuit simulator computes ∂F/∂x; jolty computes it exactly, by dual numbers, instead of by hand-written formulas.

Seeded on a parameter, they give ∂F/∂p, which gradients use. It's one mechanism for both.

The same trick works for a parameter. Run the diode's kernel with Is entered as Is + 1·ε: the current comes out carrying ∂I/∂Is. jolty does this with a second number type, Gradient (a value and its derivative with respect to one parameter), and calls the device run this way its twin.

"One mechanism" because the kernel is written once, generic over the type of number it computes with. Plain numbers give currents; Dual numbers give the currents and ∂F/∂x; Gradient numbers give ∂F/∂p. Nobody writes a derivative by hand, and the two kinds of derivative cannot disagree with the law, or with each other.

diode at the answer, x = 0.62915 V: ∂F/∂x = 1/R + (Is/Vt)·ex/Vt = 0.015345 A/V (seeded on the voltage) ∂F/∂R = −(x − Vs)/R² = 3.7085 × 10⁻⁷ A/Ω (seeded on R)
Global, through the solve: the solution x(p) is defined implicitly by F = 0, so dx/dp = −(∂F/∂x)⁻¹ ∂F/∂p.

Why "implicitly". There is no formula x = g(p): x is whatever Newton lands on. But it is pinned down by one fact: for any parameter values, the answer satisfies F(x(p), p) = 0. If that holds for every p, it keeps holding as p moves, so its derivative with respect to p is zero too. By the chain rule:

d/dp F(x(p), p) = ∂F/∂x · dx/dp + ∂F/∂p = 0 ⟹ dx/dp = −(∂F/∂x)⁻¹ · ∂F/∂p (the implicit function theorem)

Both pieces come from layer 1. In our circuit:

dx/dR = −(3.7085 × 10⁻⁷) / 0.015345 = −2.4167 × 10⁻⁵ V/Ω

Raising R by 1 Ω lowers node x by 24 µV. Re-solving the circuit at R ± 1 mΩ and differencing gives −2.41673 × 10⁻⁵: the same to six digits. Note what was not needed: the six Newton steps. The derivative uses only the answer and one linear solve with the Jacobian Newton already had.

That one product can be evaluated in two orders.

With many unknowns and parameters, and a scalar loss L that depends on the outputs, the full chain is a product of three matrices:

Right to left: one solve per parameter. This is JAX's jvp, and today's transient Sensitivity.

JVP stands for Jacobian-vector product, J · v. It answers "if I nudge the parameters in direction v, how does every output move?" Starting from the right means multiplying J⁻¹ into each parameter's column of ∂F/∂p separately: one linear solve per parameter. It is cheap with few parameters and many outputs. Today, jolty's Sensitivity(of=Transient(...)) works this way: it carries every parameter's derivative forward along the time steps (the "direct method").

Left to right: one solve per loss. This is JAX's vjp, the adjoint: today's DC and AC sensitivities, mismatch, and the new transient adjoint.

VJP stands for vector-Jacobian product, v · J. It answers the reverse question: "given how much the loss cares about each output, ∂L/∂x, how much does it care about each parameter?" Starting from the left means one solve with the transposed Jacobian, Jᵀ λ = (∂L/∂x)ᵀ, then dL/dp = −λᵀ · ∂F/∂p, one dot product per parameter. In circuit simulation this is called the adjoint method; λ is the adjoint. Backpropagation in neural networks, and jax.grad, are the same thing: VJPs chained backwards.

Which jolty features use which order today: DC and AC sensitivities, and mismatch (each output's spread from the process's random variations), use the adjoint. The transient adjoint was built that day on a branch, on main since: it runs the time steps backwards, one transposed solve per step, so its cost stays 1.5 to 2.2 times the simulation whatever the number of weights.

The boundary: everything outside the circuit, the loss and the network, is JAX's job. JAX asks jolty for exactly layer 2's vjp.

How jax.grad works: it runs your function forward, recording each operation. Then it walks backwards, and for each operation asks one question: "here is ∂L/∂(your output); give me ∂L/∂(your inputs)". That question is a VJP. JAX knows the answer for every jnp operation. It cannot look inside jolty's Rust solver, so jolty has to answer for its own operation, which is layer 2 run left to right.

custom_vjp is not a new process; it's the door to layer 2.

jax.custom_vjp is how you hand JAX a function together with its backward rule. For jolty's solve, the function is "simulate" and the rule is the adjoint above. Nothing new is computed: it is the same layer-2 VJP, exposed through JAX's door.

This is also how JAX libraries differentiate through solvers: by implicit differentiation, never by unrolling Newton. So the design isn't wrong at its root.

"Unrolling" would mean recording the six Newton steps of section 3 and differentiating through each one, as if the iteration were the function. That is the wrong object to differentiate:

  • The answer does not depend on the path: start Newton from 0.5 V or 0.7 V and you land on the same x. The derivative of the answer should not depend on the path either, and the implicit formula's does not.
  • Unrolling stores every iteration (thousands of them in a transient) and gives the derivative of the iteration, which equals the answer's derivative only once Newton has fully converged.
  • The implicit formula needs only the answer and one solve with the Jacobian Newton already factored.

JAX itself offers jax.lax.custom_root for exactly this: a root-finder differentiated through the implicit function theorem. jolty's layers 1 and 2 are that design, which is why the foundations do not need rewriting.

The debt is in the user-facing side. Each feature exposes the same maths through its own API, added one analysis at a time: Sensitivity returns Jacobians, Mismatch, the oscillator period's derivative, and now Objective. There's no shared jvp/vjp underneath.
Feature todayWhat you getOrder inside
Sensitivity(outputs)A table: every listed output against every parameter of every deviceVJP at DC and AC; JVP through a transient
Mismatch(outputs)Each output's standard deviation from the process's random variationsVJP

Four features, four interfaces, each built on its own path through the engine when its analysis was added. None of them takes "∂L/∂outputs" and returns "∂L/∂parameters", the one shape JAX asks for. That is the debt.

The uniform fix, a refactor of that surface, not the maths: for every analysis (operating point, DC sweep, AC, transient, periodic steady state), the engine exposes exactly two derivative functions, jvp and vjp, both built from layers 1 and 2.
jvp(analysis, p, dp) → dx how the outputs move for a parameter nudge dp vjp(analysis, p, x̄) → p̄ how a loss's sensitivity x̄ = ∂L/∂x reaches the parameters

Every analysis gets the same two functions with the same meaning, so a user, or JAX, never needs to know which analysis is underneath.

Sensitivity, Mismatch, the period derivative, the transient adjoint and the JAX bridge all become thin users of those two.

Then there's one process everywhere: dual numbers in the devices, implicit differentiation through the solve, jvp/vjp at the edge.

Read from the inside out: every device's law is differentiated exactly by computing on dual numbers (layer 1); the whole circuit's answer is differentiated by the implicit function theorem, using that and one linear solve (layer 2); and the result leaves jolty in exactly two shapes, JVP and VJP, which JAX and every jolty feature use (layer 3). Nothing here differentiates the same thing twice, and nothing builds an autodiff system: each layer does the one job the layer around it cannot.

5. Glossary

Node, voltage, current
A connection point; its electrical height against ground, in volts; the flow of charge through a part, in amperes.
Device, kernel
A physical part and its law (current from voltages and parameters); jolty's code for one law, written once in Rust.
Component
A Python recipe that places and wires devices; flattened into devices before simulating.
F(x, p)
The current leaving each node, from all devices together; the circuit is solved when every entry is zero.
Unknowns x, parameters p
What the simulation finds (node voltages, source currents); what you set (resistances, sizes, weights).
Newton's method
Guess, measure the error F, correct along the slope J, repeat until F is zero.
Jacobian J = ∂F/∂x
The table of how each node's current changes with each node's voltage; Newton solves with it each step.
Dual number
a + bε with ε² = 0: a value that carries its exact derivative through arithmetic.
Seeding
Starting a dual number's derivative at 1 to choose what it is the derivative with respect to.
Twin
A device run on Gradient numbers seeded on up to eight directions of its parameters, giving ∂F/∂p along each.
Implicit function theorem
If F(x(p), p) = 0 for all p, then dx/dp = −J⁻¹ ∂F/∂p.
JVP
Jacobian-vector product, J·v: push a parameter nudge forward to the outputs; one solve per direction.
VJP, adjoint
Vector-Jacobian product, v·J: pull a loss's sensitivity back to every parameter; one transposed solve per loss.
custom_vjp
JAX's way to register a function with its own backward rule, so jax.grad can pass through code JAX cannot see.
